# Archived Plans and Migration History

Completed plans are removed from `docs/plan/`; their last versions remain in the
commit trees below. Current guides describe shipped behavior. Historical decision
labels (O1–O9, R/H items, numbered binding decisions, translation slices) refer to
these archived designs, not to live files in the working tree.

This file is an index: which plans finished, where each plan's last text is, and which
guides own the result. A plan's slice commits, decisions, and measurements are in its own
file (the `Status` line and the slice notes) and in the commit messages. What a plan left
open is in the backlog: [manual checks](../backlog/manual-checks.md),
[deferred work](../backlog/deferred-work.md), and
[decisions to verify](../backlog/decisions-to-verify.md). Archiving an implemented design
does not certify its pending manual checks. [Active work](../plan/README.md) remains
separate.

Until 2026-11-11 this file also carried every plan's run notes (slice commits, test
counts, merges, follow-ups). `git show 86d820862:docs/archived-plan/README.md` is the
last version with them; the numbers they held are in
[plan close-out figures](../reports/measurements/plan-close-out-figures.md).

## Retrieve a Historical Plan

Use the commit and original path of the plan's table row together, for example:

```sh
git show 317a97ce:docs/plan/model-profiles.md
git show 4d1542d92:docs/plan/upstream-intake-2.md
git ls-tree -r --name-only 9d09288b -- docs/plan/PLAN.md docs/plan/phases/
```

A historical reference such as `docs/plan/chat-binding.md` is retrievable with
`git show 809b35cc:docs/plan/chat-binding.md`; it is not a current architecture guide.

## Archive Procedure

Remove a completed or retired plan and its active-list link, then add one table row here:
its last existing commit and path, and the guides that own the result. Verify with
`git show <commit>:<path>` before deleting the file. This file takes no run notes, so
before the plan file goes:

- its `Status` line names each slice's commit;
- a decision made during the run is in the owning guide, or in the plan's own text when it
  changed nothing a guide describes;
- a figure the run measured is in a report under `docs/reports/measurements/`;
- what the plan left open is in the backlog: a check that needs a person, a device, or a
  real provider in [manual checks](../backlog/manual-checks.md), and put-off work in
  [deferred work](../backlog/deferred-work.md).

Keep operational contracts in current guides rather than asking readers to load a
historical plan.
