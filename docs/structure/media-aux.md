# Media and Auxiliary Features: TTS, Image Generation, Translation, Playground

## Scope

- Owns:
  - text-to-speech providers and plugin TTS hooks,
  - AI image generation backends,
  - translation (providers, HTML translation, caches, presets, `edittrans` regex),
  - image type detection and compression,
  - the aux-model selector UI,
  - the playground tool screens,
  - legacy 3D and voice files.
- Paths:
  - `src/ts/process/{tts,ttsHooks,stableDiff}.ts`
  - `src/ts/translator/*`
  - `src/ts/media/*`
  - `src/ts/voice.ts` (unused)
  - `src/ts/3d/*` (unused)
  - `src/lib/UI/3DLoader.svelte` (unused)
  - `src/lib/Playground/*`, except `PlaygroundMenu` (→ `ui-theming.md`), `PlaygroundEmbedding` (→ `memory.md`), `PlaygroundMCP` (→ `plugins-mcp.md`), and `PlaygroundRegex`/`Syntax`/`Parser` (→ `scripts-triggers.md`)
  - `src/lib/Setting/Pages/Translation/TranslatorPresetSettings.svelte`
  - `src/lib/Setting/Pages/Model/AuxModelSelectors.svelte`
- Not here:
  - Aux-model request routing → `llm-requests.md` (`requestChatDataMain`).
  - Inlay storage → `chat-pipeline.md` (`files/inlays.ts`).

## Files

TTS:

- `process/tts.ts`:
  - `sayTTS(character|null, text)`: provider switch on `character.ttsMode`. Providers: `webspeech`, `elevenlab`, `VOICEVOX`, `openai`, `novelai`, `huggingface`, `vits`, `gptsovits`, `fishspeech`. Captures the Stop generation at entry and carries it through the playback context, including the GPT-SoVITS gain path. Each run also registers its own `AbortController` (`activeSpeechControllers`) and passes its signal to every provider request (`fetch` and `auxFetch` as `signal`, `globalFetch` as `abortSignal`); the Hugging Face 503 `estimated_time` retry waits on that signal. Because `globalFetch` answers an abort with `ok: false` instead of throwing, each branch checks the signal after its request and body read before it alerts or throws, and after the unabortable awaits (`translateVox`, `runTranslator`, `loadAsset`, `runVITS`) before going on. A run whose signal was aborted ends silently.
  - `stopTTS`: advances the generation, aborts every registered run's controller (pending provider requests and the Hugging Face retry wait; the provider's remote job is not cancelled), stops and retires every source in `activeSpeech`, closes their audio contexts and every context still decoding (`pendingContexts`), and cancels Web Speech. The chat menu exposes Stop for every enabled mode, VITS included.
  - Voice lists: `getWebSpeechTTSVoices`, `getElevenTTSVoices`, `getVOICEVOXVoices`, `getNovelAIVoices`, `oaiVoices`.
  - `FixNAITTS`.
  - Internal: `playAudio` runs `runPostprocessorPipeline`, then `playProcessedAudio` decodes and starts the source. The gain path and VITS (`runVITS` only synthesizes and returns the WAV bytes; no hooks run on them) share `playProcessedAudio`: it checks the captured generation before starting, tracks each source/context in `activeSpeech`, and retires it on `ended`; a cancelled decode or a decode failure closes the unused context, and a decode that rejects after Stop closed its context alerts nothing.
- `process/ttsHooks.ts`: `BeforeTTSContext`/`AfterTTSContext`, the pre/postprocessor register/remove/list functions, and `runHookPipeline`, which is sequential, supports `skip`, and ignores errors.

Image generation:

- `process/stableDiff.ts`:
  - `stableDiff(currentChar, prompt, target = {})`: builds a prompt with `requestChatData(..., 'submodel', target.signal)`, then calls `generateAIImage` with `{ signal: target.signal }`. `target` keeps `chatRef`, `pluginContext`, and `check`, and accepts `signal?: AbortSignal`; cancellation applies only when the caller supplies a signal.
  - `generateAIImage(genPrompt, currentChar, neg, returnSdData, options: { signal?: AbortSignal; orientation?: "landscape" | "portrait" } = {})` dispatches on `settings.memoryTranslateMedia.sdProvider`: `webui`, `novelai` (ZIP → `processZip`), `dalle`, `stability`, `comfy`/`comfyui`, `fal`, `Imagen`, `openai-compat`, `wavespeed` (polling). The optional signal reaches every request, including character-image reads through `readAsset` and their retries; ComfyUI's 1 s and Wavespeed's 3 s polling waits are abortable. Both entry points reject an aborted run with the signal's own reason, without an alert or image delivery; checks after awaits cover response bodies and image processing. ComfyUI polls `/history/{prompt_id}` (the id URL-encoded), reading `[prompt_id]` from the answer; a 404/405 switches once per run to `/history` before parsing the body, and any other non-OK history answer fails. The deadline is checked before every history request. `orientation` reaches only NovelAI: `applyImageOrientation` puts the longer configured side on the width for `landscape` and on the height for `portrait` (txt2img and img2img); the configured size is used as is without one, and every other provider ignores it. Every success uses `deliverGeneratedImage`, which checks the signal before returning the image URI for `"inlay"` or updating `CharEmotion` from the store's value at write time and returning `returnSdData`.

Translation:

- `translator/translator.ts`:
  - `translate`: memory cache keyed by text and `memoryTranslationContext` (the direction-independent language pair, including the model's `ja`/`en` choice, provider, input language, experimental Google flag, DeepLX URL, and DeepL free/paid option), skipped for the LLM translator (`usesMemoryCache`). Forward and reverse lookups share pairs within one context. Only `translate` writes this cache, after `runTranslator` returns and only if the current context still matches the captured one; direct `runTranslator` callers such as TTS and the playground do not populate it. `writeMemoryCache` and `dropMemoryCacheEntry` count both strings plus `MEMORY_CACHE_ENTRY_OVERHEAD` (64 UTF-16 code units per pair for its Set and two Map entries) toward `MEMORY_CACHE_CHARS` (4,000,000); the least recently used pairs across contexts leave first, so tiny entries also consume the budget.
  - `runTranslator`: cuts the text with the server's `translateProtectingLines` (the lines between two empty or asset lines go out as one chunk joined with `\n`, the protected lines kept); for the LLM translator with a preset on Send Text As-Is (`sendTextAsIs`) the whole text goes to `translateLLM` in one call, its reply returned as is. With Exclude Chain-of-Thought (`excludeThoughts`) and without As-Is, the LLM translator's text loses its reasoning blocks (`stripTranslatorReasoning`) once, whole, before the line cut, and the chunks go to `translateLLM` as prepared (`inputPrepared`: not stripped again, the strip is not idempotent, and keyed apart from raw text); a chunk's failure (`translateLLM`'s `failure` flag) returns the whole text as given.
  - `translateMain` dispatches to LLM, DeepL, DeepLX, experimental Google, or direct Google GTX (any other `translatorType`, `"none"` included, reaches Google). Unless `noWaitForTranslate` is on, each DeepLX request takes the next free slot (`waitTrans`), 3 s after the one before it, and waits for it.
  - `translateHTML`: collects DOM translation jobs before dispatch, keeping the `script`, `style`, and `translate=no` skips and combined paragraphs' span restructuring. DeepLX sends sequential `■`-joined batches up to 5,000 characters, including the final partial batch, and retries each chunk separately when the separator count disagrees. Other providers translate jobs with at most ten requests in flight. Both paths then apply the results through the same text/display-script/Markdown handling before `applyEdittransRegex`.
  - `translateLLM`: runs the preset's steps (`getCurrentTranslatorPreset`: the selected chat's translator preset, else the global selection; `runTranslator` reads it once for all its chunks, and the playground passes `globalPreset` for the global one) through `runTranslatorPipeline` (`shared/translation/pipeline.ts`), each step a `requestChatData(..., 'translate')` with the step's profile as `profileId` when its `model` names one (else the `translate` slot); a failed step alerts and returns the source. Without Send Text As-Is, each `<risu-style>` block is sent as a `<style-data>` placeholder and restored in the reply; with it, the text and the reply are kept as they are. With Exclude Chain-of-Thought (`stripInput` unless the caller prepared the text), the reasoning blocks leave the text after the cache read and before the placeholders; a text left blank caches and returns `""` without a request, and a failure returns the text as given (and sets the caller's `failure` flag). On the rendered path `ParseMarkdown` has already turned `<Thoughts>` into `<details>`, so only raw tags (the `translateBeforeHTMLFormatting` text) are stripped. Cached in LocalForage `LLMTranslateCache` (`LLMCacheStorage`) under `llm:<hash>:<source>`, the hash (`translationSourceHash`) of the pipeline signature, the languages, the translator note, and `sendTextAsIs` and `excludeThoughts` each when it is on (plus `inputPrepared` for `runTranslator`'s prepared chunks) (keys without them preserve the legacy cache format; the key's text is the caller's, before any strip, except `runTranslator`'s protected chunks, keyed by the chunks of the stripped text), all read once into a detached context before any await (`llmTranslationContext`; `translateHTML` reads it once for both its cached-only check while generating and the translation). The context also captures the request ids every step runs with (`runTranslator` captures them once for all its chunks, with the preset) (`requestIds`: the settings views' prompt preset, model preset, and persona, as a chatless request would read them), so a chat switch during a multi-step run does not move the later steps; they are not in the cache key. `llmTranslationCacheKey(text)` is the key as `translateHTML` translates now; the translation editors in `Chat.svelte` keep that full key and write back to it (`readLLMCacheEntry`/`writeLLMCacheEntry`). `getLLMCache(text)` and `searchLLMCache(partial)` (plugin API v3: source-text keys, current context only) read the current context (the selected chat's preset). Entries keyed by the bare source (before the pipeline) are never read.
  - `applyEdittransRegex`: collects `presetRegex`, then module scripts, then character scripts, keeping `type === 'edittrans'`.
  - Also `translateVox`, `isExpTranslator`.
- Bergamot (the local Mozilla translator, "Firefox" in the select) was removed: the server normalizer turns a stored `translatorType: "bergamot"` into `"google"` with `translator` empty (translation off, which also keeps every chat's `autoTranslate` inactive) and `useAutoTranslateInput` off, so nothing is sent to an online translator until the user turns translation on again. Its HTML option `htmlTranslation` is a dropped field.
- `translator/presets.ts`: `TranslatorPreset {id, name, steps, sendTextAsIs?, excludeThoughts?}` (declared in `shared/settings.ts`; `sendTextAsIs` and `excludeThoughts` stored only as `true` with `TranslatorStep {id, name, enabled, prompt, maxResponse, model, outputKey?}`; `createTranslatorPreset`, `normalizeTranslatorSteps`, `isTranslatorPreset`, and `defaultTranslatorPrompt` live in `shared/translatorPresets.ts`; the `.risutl` codec writes no id and an import gets a fresh one), `getCurrentTranslatorPresetFromState` (the valid preset whose id is `translatorPresetId`, else the first; it never writes the state), and the `.risutl` codec (`encodeTranslatorPresetFile`/`decodeTranslatorPresetFile`: encrypted msgpack, `type: 'translator-preset'`. Version 1, a payload of `name`, `prompt`, `maxResponse`, is written when it holds the preset without loss (Send Text As-Is and Exclude Chain-of-Thought off, one enabled step on the `translate` slot, no output key, the default name `Step 1`) and decodes to one step; one carrying `sendTextAsIs` or `excludeThoughts` is refused. Otherwise version 2, a payload of exactly `name` and `steps` and the optional booleans `sendTextAsIs` and `excludeThoughts` (each written only when on) (1–5, each exactly `name`, `enabled`, `prompt`, `maxResponse`, `model`, and an optional `outputKey`; no preset or step id). Decoding checks every level and refuses another shape (a Fastify file), an invalid output key, or one used twice; a profile step keeps its profile id (it runs where that profile exists and shows as missing elsewhere). A blank name imports as "Imported Preset").
- Server translation: `POST /api/translate/message` (`server/src/translation/runner.ts`, `self-host-server.md`; the path and the body/answer types in `shared/translation/route.ts`) translates a stored message's source text with the same pipeline and stores it on the message (`Message.translation`, the `setTranslation` op). A preset on Send Text As-Is sends the whole source through one pipeline run and stores the reply as is; otherwise (the default) `translateProtectingLines` cuts the source at empty and asset lines and runs the pipeline on each other part in turn, under the message's one deadline, CBS budget, and write. Unlike `translateLLM` it sends the source without `<risu-style>` protection, and runs without the tab's plugin interceptor, plugin providers, and `request` trigger. A step on a profile sends `profileId` (a deleted profile fails the run, 502); every step runs with the run's `modelPresetId`. History slots in the prompts of the steps that run are built once per message, when the first pipeline run starts, from the run's chat copy (`buildTranslatorHistory`, the counts by `translatorHistorySlotCounts`), each count yielding a turn and checking the run before and after it; the same history serves every part and step, in both modes. A preset on Exclude Chain-of-Thought strips the reasoning blocks from the whole source once before the As-Is run or the line cut (a source left blank stores an empty translation without a request) and from each history entry's source and fresh translation (`transformText`, applied by `collectTranslatorHistory` after the freshness check); `sourceHash` stays the stored text's.
- `llmTranslationTarget` (`memoryTranslateMedia`, `"message"` by default, any other value normalized to it) picks the LLM translator's path: `"message"` is the stored translation, `"rendered"` today's `translateHTML` path with its browser cache.
- Stored translation in the tab, `translator/storedTranslation.svelte.ts`: `usesStoredTranslation()` (LLM on `"message"`), `freshTranslation(message)` (the whole record while its hash matches; an empty text counts), `heldMessage`. `requestStoredTranslation(ref, id, { force, follow? })`: one request per message per tab (a second call gets the running one); it captures the chat's display ids (`chatDisplayIds`) and the text's hash, saves every pending change (`flushResources`; `GenerationBlockedError` alerts `chatGenerating`, a conflict that discarded this chat's work or a text or display id changed meanwhile stops with a retry message), POSTs with the epoch header (a 21-minute wait for this tab only, two server deadlines for a request that waits on an older text's run, authentication and the body included, and nothing sent once it passed; the run continues on the server), maps 412 to `epochMismatch` (no other alert), 409 `generating`/`chatBindingMismatch` to their strings, `ignored` to `translationSourceChanged`, anything else to `translationFailed` with the server's error or the status, and validates the answer (`isTranslateMessageAnswer`). `follow` is the server hand-off's: `followStoredTranslations` runs it for each id of a job's `translating` notice (`jobChannel.ts`). It skips the save barrier and the stability checks and says nothing on `ignored` or missing display ids; the unforced POST joins the run in flight, so the row shows loading until the translation arrives or the run's failure is reported. Its failures go through `follow.report`, which the job channel queues as an `alertError` notice, so one never replaces a question the next send shows. A follow that arrives while a request for the message runs (a Continue's hand-off) follows again once it settles, the message pending throughout. A run that already ended answers `fresh`, or the POST starts a new run (a failed one is tried once more). Notices are best effort: a tab that was disconnected when the job sent one shows no loading state and no failure, and gets the translation through its chat refresh. The answer is not displayed by itself: the request stays pending (at most 15 s) until the held message holds the stored translation the chat's resource refresh brings, or its text changed. Its pending set and the rows' show/hide choices are reactive maps keyed by chat and message id, so a remounted row keeps both. `beginStoredTranslationEdit` captures an edit session (the chat, the message, the source hash, a copy of the fresh translation); `saveStoredTranslationEdit` writes `setMessageTranslation` with that hash, the base's `presetId` and `targetLanguage`, `translatedAt` now, and `edited: true`, and alerts and returns false when a generation locks the message, it is gone, or its text changed (`translationEditStale`); true means queued.
- `Chat.svelte` on the stored path (a row with a `messageId` in the displayed chat; the greeting and bookmark previews keep the rendered path): the row asks for the translation by its choice, else its chat's `autoTranslate` (`chatAutoTranslate`: the flag while a target language is set; it shows stored translations by default; the tab never requests one automatically; the server translates a send's messages). It shows the fresh stored translation as `displayMessage`, which goes through `risuChatParser` and `ChatBody` like the text. The toggle hides the translation when it is on (shown, or asked for and pending); otherwise it shows it and, without a fresh translation or a pending request, requests one (a locked message alerts). Retranslate (disabled while pending) confirms (`retranslateConfirm`) with the message captured before the dialog, rechecks it, then requests with `force`. Edit translation is enabled only with a fresh translation and nothing pending; a refused save keeps the editor open, and an open editor keeps its Save and Cancel whatever the settings do meanwhile. The partial editor's translated view is the shown stored translation, edited through a captured session (`stored:<n>` keys); its `saveTranslation` callback returns whether the write was taken, and a refused edit keeps its draft; a save that ends after a cancel or a newer edit leaves that editor alone, and saves do not overlap. `ChatBody` on the stored path (`storedPath`) renders `msgDisplay` without the rendered translation, applies the `edittrans` scripts to a shown stored translation before Markdown (`applyEdittransToStoredTranslation`, as the `translateBeforeHTMLFormatting` path does), and shows the loading spinner (`showTranslationLoading`) while a requested translation is pending. The toggle's `translating` animation is the pending state there. `PartialEditController` never falls back to editing the original from a translated view whose translation context is missing (both paths).
- Bilingual display: `translator/bilingualInterleave.ts` `bilingualInterleave(source, translation, { emphasize, sentenceBreaks })` pairs each non-blank unit of the source (a line, or a whole code fence) with the next one of the translation, by position, in `x-risu-bilingual-pair` wrappers (the de-emphasized side `x-risu-bilingual-muted`); `parser/sentenceBreaks.ts` `insertSentenceParagraphBreaks` first splits prose lines every N sentences (`Intl.Segmenter`, never inside an open quote, never in code, HTML, headings, lists, quotes, tables, or rules). `Chat.svelte` passes `bilingualDisplay` (the stored message's text after the row's display CBS pre-pass, `displaya`, as the translation gets it, and the chat's emphasis and pairing) to `ChatBody` while the stored translation is shown and the chat's `bilingualDisplay` is on; `ChatBody` applies `edittrans` to the translation, interleaves, and renders through the display path, so the display scripts see the wrappers between the lines. Every rendered body goes through `pruneEmptyBilingualPairs` (parsed as a `<template>` fragment, so a leading `<style>` is kept; untouched without a pair): sides and pairs that render nothing are dropped, and a pair showing only an image keeps one unmuted side. The CSS is in `src/styles.css` under `.chattext`. Partial edit is off on a row that shows a pair.
- `shared/translation/pipeline.ts` (pure, shared with the server runner): `translatorStepsToRun` (the enabled steps, else the first), `fillTranslatorSlots` (one pass: `{{slot}}`, `{{slot::from}}`, `{{slot::content}}`/`{{solt::content}}`, `{{slot::prev}}`, `{{slot::out::KEY}}` (a `Map`, empty when unset), `{{slot::tnote}}`, and the history slots `{{slot::history::N}}`/`{{slot::historytrans::N}}` from the caller's `history`, empty without one or for an invalid N), `translatorHistorySlotCounts` (the valid history counts in the executed prompts, by the same one-pass match), `parseTranslatorChatML`, `buildTranslatorStepMessages` (ChatML wins; else the system prompt, plus the previous output as the user message unless the prompt holds an input slot), `stripTranslatorReasoning` (`<Thoughts>`/`<think>` blocks out of every step's output), `translatorPipelineSignature`, `runTranslatorPipeline`, `isProtectedTranslationLine` and `translateProtectingLines` (the line protection without Send Text As-Is, for the server runner and the tab's `runTranslator`). `shared/translation/historySlots.ts`: `translatorHistoryCount` (all digits, 1 to 50), `translatorHistoryMaxTokens` (a finite number above 0, else 2048), `collectTranslatorHistory` (an optional `transformText` on each source and translation; walking back from the row before the message: `disabled: "allBefore"` ends the walk, comment or not; disabled and comment rows are skipped; `source` is the raw `data`, `translated` the fresh `storedTranslation`, an empty one included), `translatorHistoryBlock` (`role: body` then `\n\n---\n\n`, `user` or `char`), and `buildTranslatorHistory` (per count, the newest N entries, the oldest whole ones dropped while their source and translation blocks, an empty translation block for an entry without one, pass the budget; each entry counted once; returns `TranslatorHistory`). The tab passes no history, so its history slots fill in empty. CBS is never evaluated in a translator prompt (the old `parseChatML` path ran `risuChatParser` on ChatML contents, the substituted source included).

## Flows

- TTS triggers:
  - Manual: the `Chat.svelte` button → `sayTTS(null, msg)`.
  - Automatic: `sendChat` when `db.ttsAutoSpeech`.
  - Command: `command.ts` `speak`.
- `sayTTS` steps:
  1. Strip asterisks and optionally keep only quoted text.
  2. Run the preprocessor hooks.
  3. Call the provider.
  4. `playAudio` runs the postprocessor hooks and plays. Web Speech and VITS bypass the postprocessors.
- Image generation, emotion mode: the server job's `imggen` callback in `jobChannel.ts` → `stableDiff` → `generateAIImage(..., "")` → `deliverGeneratedImage` updates the transient `CharEmotion`; the callback answers `shown !== false`.
- Image generation, inlay mode:
  1. Callers: `inlayScreen.ts`, triggers, Lua `generateImage` (the server's `generateImage` callback, whose payload carries the script's `orientation` when it gave one; the tab passes it on only when it is `landscape` or `portrait`), the playground.
  2. `generateAIImage(...,'inlay')` returns a data URI.
  3. The caller must call `writeInlayImage` and insert `{{inlay::id}}`.
- Display translation: on the rendered path `ChatBody.svelte:markParsing` switches on its chat's `autoTranslate` (the `autoTranslate` prop from `Chat.svelte`; a change restarts the row), `autoTranslateCachedOnly`, `translateBeforeHTMLFormatting`, and `legacyTranslation`, then calls `translateHTML`. While the row's message is streaming (`Chat.svelte` passes `streaming` from `isStreamingMessage`, in every streaming mode), `markParsing` renders the original without the auto-translate decision or `translateHTML`, and the translation runs once when streaming ends. On the stored path `Chat.svelte` swaps in the stored translation and `ChatBody` renders it as text.
- Input translation: `DefaultChatScreen.updateInputTransateMessage`, when `useAutoTranslateInput`.

## State

- Per-character TTS config: `ttsMode`, `ttsSpeech`, `voicevoxConfig`, `naittsConfig`, `gptSoVitsConfig`, `fishSpeechConfig`, `oaiVoice`, `hfTTS`, `vits`.
- DB keys and URLs: `elevenLabKey`, `voicevoxUrl`, `NAIApiKey`, `huggingfaceKey`, `fishSpeechKey`, ... The Voice & Emotion page shows the OpenAI key (Model › API Keys) and `NAIApiKey` (Image Generation's NovelAI block) as status and a link, not as inputs; DALL-E and Imagen show the OpenAI and Google keys the same way ([settings-i18n](settings-i18n.md)).
- Image generation: `db.sdProvider` plus per-backend settings.
- `CharEmotion`: `{[chaId]: [img, img, ts][]}` (not persisted).
- Chat translation settings: the chat fields `translatorPresetId`, `autoTranslate`, `translateBotOnly`, `bilingualDisplay`, `bilingualEmphasis`, `bilingualSentences`, stored as sent and carried by the chat summary (list fields, `CHAT_TRANSLATION_FIELD_TYPES`), read through `shared/translation/chatSettings.ts` (`readChatTranslationSettings`: missing or malformed is off/unset). The global `autoTranslate` is a dropped field, not copied anywhere. `resolveTranslatorPreset(chat, presets, selectedId)`: the chat's preset when it names one that exists, else the global selection (`selectedTranslatorPreset`), reporting `missing` for a deleted one; nothing is rewritten when a preset is deleted. The server runner resolves the translated chat's; the tab (`src/ts/translator/chatTranslation.svelte.ts`) the selected chat's. A new chat copies the character's selected chat's six fields under `newChatBinding: "inherit"` (`initialChatTranslation`, a deleted preset id kept) and none under `"empty"`; copies and branches keep them; `importChat` keeps them but drops a `translatorPresetId` that names no preset here (`importedChatTranslation`). ## Coupling

- TTS depends on `database.svelte.ts`, `globalFetch`, `runTranslator` (Hugging Face non-English), `transformers.ts:runVITS` (synthesis only; it never opens an `AudioContext`), and plugin v3 (hook registration).
- The VITS model import (`transformers.ts` `registerOnnxModel`, the character's TTS settings) takes the picked zip as a `File` and reads it by its central directory (`process/zipFile.ts` over `shared/charxImport.ts`'s parsers), never scanning entry bytes for signatures. Each kept member (`.onnx`, under 10 MB compressed, or a `.git` path; no directories) is read and inflated only when its `saveAssets` slot is free (two at once) and the members are written in batches; a member over `MAX_ONNX_MEMBER_BYTES` (100 MiB less 64 KiB, so its record fits the server's body limit) is skipped and named in the closing message. An unreadable zip or a failed save alerts and returns nothing.
- `stableDiff` depends on `requestChatData`, `CharEmotion`, `processZip`, and inlays.
- The translator depends on the parser (`ParseMarkdown`, `applyMarkdownToNode`, `postTranslationParse`, `risuChatParser`), `requestChatData`, the script transform (`serverProcessScript`), platform flags, and localforage.
- The media utilities are used by card import/export, modules, and inlays.

## Invariants

- Provider discriminators are literal and case-sensitive: `VOICEVOX`, `Imagen`, `openai-compat`, `comfy` vs `comfyui`. Saved `ttsMode: 'none'` is migrated to `''`.
- TTS hooks apply only on paths through `playAudio`. The GPT-SoVITS gain path must still call `runPostprocessorPipeline`.
- `generateAIImage(..., 'inlay')` does not persist its result. The caller must persist it.
- Keep the `.risutl` format constants stable.
- A translator preset always has 1 to 5 steps: the server normalizer (`normalizeTranslatorSteps` through `createTranslatorPreset`) turns the old `{ prompt, maxResponse }` shape into one inherited step. The tab creates and imports presets with `createTranslatorPreset`, so what it writes is what the server stores. The step editor finds each step by the preset's id and the step's id at every read and write (nested steps have no by-id identity in the records) and writes only what the normalizer keeps as is: a blank name and an invalid or already used output key stay local drafts, shown with a hint and dropped for good once the stored value they were typed over (for a key, also the other steps' keys) changes; a cleared or invalid response size is not written, and the field shows the stored size again when committed. So the tab's copy stays the server's normalized text.
- `translateHTML` must preserve markup boundaries and the `translate=no`/`script`/`style` skips. It applies `edittrans` after translating (`applyEdittransRegex`: the one regex the tab still runs, a plain `RegExp` replacement with no Lua or trigger). Its `editdisplay` call runs on the server (`serverProcessScript`, target kind `translation`), with the context captured when `translateHTML` starts; without a context (a chat not saved on the server yet) the translated text stays as it is.
- Aux-model keys use the persisted misspelling `seperate*`. `submodel` is not an auxiliary slot: it always uses the sub slot. The root `seperateModels.<mode>` is a derived model id (the slot's profile's, `""` for an unset or dangling slot), never stored.
