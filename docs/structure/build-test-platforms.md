# Build, Test Harness, Service Worker, Release

## Scope

- Owns:
  - package scripts,
  - Vite, Vitest, and TypeScript config,
  - the test inventory,
  - the PWA service worker and manifest,
  - the userscript bridge,
  - version bumping,
  - repo dotfiles.
- Paths:
  - Root config: `package.json`, `vite.config.ts`, `vitest.config.ts`, `vitest.setup.ts`, `vitest.lucideImports.ts`, `vitest.testNetwork.ts`, `vitest.testNetwork.test.ts`, `vitest.testNetwork.node.test.ts`, `playwright.config.ts`, `tsconfig.json`, `tsconfig.node.json`, `version.json`
  - Dotfiles: `.gitignore`, `.ignore`, `.gitattributes`, `.npmrc`, `.vscode/`
  - `public/sw.js`, `public/manifest.json`
  - `util/risuUserscript.user.js`
  - `util/agentDev.mjs`, `util/agentDevHost.mjs`, `util/agentDataSandbox.mjs` (the `dev:agent` / `dev:human` full-stack runner)
  - `util/agentTest.mjs`, `util/agentTestReporter.ts`, `util/agentTestResults.mjs` (the `test:agent` wrapper, its reporter, and their shared summary line and rerun of failed files), `util/agentE2e.mjs` (which specs `test:agent --e2e` selects), `util/requireHuman.mjs` (the human gate)
  - `util/overloadTest.mjs` (the `test:overload` runner)
  - `util/testInventory.mjs` (the `check:tests` test inventory check)
  - `util/ci/check.sh` and `.gitlab-ci.yml` (the CI gate and its GitLab pipeline)
  - `util/playwright/` (browser automation helpers and capture scripts), `e2e/` (Playwright specs)
  - `util/heap/` (V8 heap snapshot analysis)
  - `util/upstream/` (the upstream RisuAI `.bin` compatibility check)
- Not here:
  - `globalApi.svelte.ts` `fetchNative` → `global-api.md`.
  - The self-host server → `self-host-server.md`.

Config files:

- `vite.config.ts`:
  - Plugins: Svelte, Tailwind (`@tailwindcss/vite`), `vite-plugin-wasm`, conditional `@rollup/plugin-strip`.
  - Dev server defaults to port 5174 with `strictPort`, listening on `0.0.0.0` (`util/agentDev.mjs` passes `--host`/`--port`). `cacheDir` is `RISU_VITE_CACHE_DIR` when set, else Vite's `node_modules/.vite`. The watcher ignores the server storage (`save/`, `save-agent/`, its lock, and its staging and previous copies). It injects `globalThis.__NODE__ = true` (plugin `risu-node-flag`, `apply: "serve"`, so `dist/index.html` never carries it) and proxies the server routes (`/api`, `/proxy`, `/proxy2`, `/hub-proxy`, with WS) to `RISU_DEV_SERVER` (default `http://localhost:6001`). See `self-host-server.md` for the dev caveats.
  - `envPrefix` is Vite's default (`VITE_`). `build.minify` is `oxc`.
  - Alias `src` → `/src`. Workers are built as `es`.
  - Neither `define` nor `manualChunks` is set.
- `util/requireHuman.mjs`: the human gate. `requireHuman(command)` prints a notice (what to run as an agent, how to set `HUMAN` as a person) and exits with 1 unless `CI`, `HUMAN`, or `AGENT_TEST` is set; it exits instead of throwing so the caller shows no stack trace. `vitest.config.ts` calls it at load, which covers `pnpm test`, `pnpm test:slow`, `pnpm test:all`, and a direct `vitest` (every run loads the config once in the main process; the Vitest VS Code extension loads it too, so that editor needs `HUMAN` in its environment). `pnpm test:e2e` runs the file's command-line form (`node util/requireHuman.mjs "<command>"`) before Playwright; agents run the specs with `pnpm --silent test:agent --e2e` instead. `util/agentTest.mjs` sets `AGENT_TEST=1` for the run it supervises. Agents must use the wrapper and must not set `HUMAN` or `AGENT_TEST` themselves to bypass this convention.
- `vitest.config.ts`: `requireHuman("vitest")` at load (see above), Svelte plugin (`configFile: false`: there is no `svelte.config.js`, and the lookup would log a line on every run), the test-only `lucideImports` plugin, `src` alias, browser resolve conditions, `happy-dom`, setup file `vitest.setup.ts`, default include pattern, `e2e/**` excluded (Vitest's default include also matches the Playwright `*.spec.ts` files), and `.claude/**` excluded (Claude Code worktrees under `.claude/worktrees/` are checkouts of other branches, so a run in the main checkout would collect their tests too).
- `util/agentTest.mjs` (`pnpm --silent test:agent [--force] [--verbose] [--all] [--slow-tests[=<ms>]] [--no-rerun] [vitest args]`): `pnpm test` for agents, and the only entry point that runs tests without `CI` or `HUMAN` (the child gets `AGENT_TEST=1`; `test:overload` goes through it). It runs `vitest run --tags-filter=!slow` (`--all` drops the tag filter, like `pnpm test:all`; `--tags-filter=slow` is `pnpm test:slow`; an explicit `--tags-filter` replaces the default; other arguments, such as a file filter, pass through) with `util/agentTestReporter.ts` and caches the result in `node_modules/.cache/agent-test/<args hash>.json`. The key is the working tree's `git write-tree` id, taken from a copy of the real index with every change staged (untracked files included, `.gitignore` honored, so unchanged files keep their stat cache), plus the Node and Vitest versions and the arguments. On a hit it prints a `[agent-test] cached result ...` line, the stored stdout, and exits with the stored code; failures are cached too, since the same tree gives the same result, and `--force` runs anyway and replaces the entry. Stderr of the run (Node warnings, worker-thread traces from passing tests) is held back: a passing run only reports its line count, a failing run prints the last 60 lines after the report, `--verbose` prints all of it. Outside git it runs without the cache. An interrupted run caches nothing. `pnpm --silent test:agent` also drops pnpm's own banner lines. `--slow-tests` (or `--slow-tests=<ms>`; default 1000 ms) makes the reporter also list the passed tests that took longer than that, as a warning that never changes the exit code; the wrapper consumes the flag (Vitest never sees it) and hands the threshold to the reporter in `RISU_REPORT_SLOW_TESTS_MS`. The flag is part of the cache key like any argument; a cached replay shows the stored run's durations, and `--force` measures again. `test:overload` passes it through. When a run fails, the wrapper runs each failed file again alone, one at a time and with the same arguments minus the file filters (`parseCLI` from `vitest/node` finds them), after the full run; the reporter's output is held until then (it prints nothing while tests run anyway). A file whose run alone passes counts as passed: its full-run failures are listed in a `FLAKY <n> tests failed in the full run and passed when their files ran again alone (load-sensitive: a warning, not a failure; ...)` block with each test's first error line, appended to `node_modules/.cache/agent-test/flaky.jsonl` (one JSON line per test: time, tree, arguments, name, message), and its counts come from the run alone. A file that fails again shows the failures of its run alone after a `RERUN <file> failed again when run alone` line, instead of its full-run failures. The summary line then counts the merged result and ends with `<n> failed files rerun alone in <s>s`, and the exit code is 0 only when every rerun passed. Nothing is rerun when more than 5 files failed (`MAX_RERUN_FILES`: taken as a real break, and a `[agent-test] not rerun: ...` line says so), when the run had unhandled errors (they belong to no file), or when the run was interrupted or wrote no results. `--no-rerun` turns the rerun off (`test:overload` passes it, since a failure under its overload is what it looks for); whether the rerun is on is part of the cache key. The reporter hands the wrapper its per-file results in a temporary JSON file named by `RISU_REPORT_RESULTS_FILE`.
- `pnpm --silent test:agent --e2e [<spec>...] [--all] [--e2e-since=<rev>] [--force] [--verbose] [playwright args]`: the Playwright specs in `e2e/` for agents (`pnpm test:e2e` is for people), through `node_modules/@playwright/test/cli.js test --reporter=dot` with the same held stderr and the same cache (keyed by the Playwright version and the selected specs). Run the specs the change reaches, not the whole set: named specs (`e2e/openChat.spec.ts` or `openChat.spec.ts`) run as named, `--all` runs every spec (about 12 min, 33 tests), and with neither the wrapper selects them from the changed files (`util/agentE2e.mjs`): the files changed since HEAD (staged, unstaged, deleted, both names of a rename, untracked), or since `--e2e-since=<rev>` to count committed work too. A spec is selected for a changed file when it is that file, imports it through its harness (relative static imports followed through `e2e/` and `util/playwright/`), names it in its text (the repository path, `/src/...` dynamic imports included; the file name when no other tracked file has it; or a parent directory, such as a fixture directory it reads), or when the file is one every spec runs on (`playwright.config.ts`, `util/playwright/globalSetup.mjs`, `util/playwright/stack.mjs`, `vite.config.ts`, `index.html`, `pnpm-lock.yaml`). Guides (`docs/`, `handover/`, `*.md`) and unit tests (`*.test.*`) never select a spec. The wrapper prints each selected spec with the changed files that selected it and lists the changed files no spec names; when nothing is selected it lists the specs with their first comment sentence and exits with 2, so the agent names the specs that cover the behavior it changed. Selection is by name, not coverage: a component no spec names (a chat screen file, say) selects nothing even when a spec drives it. One e2e run at a time per machine: the stack's ports are fixed (server 6101, Vite 5201, `util/playwright/globalSetup.mjs`), so a run first listens on port 6199 as a lock every checkout and worktree sees (waiting up to 30 min while another run holds it), then waits up to 2 min for the stack's ports (a stack an interrupted run left behind) and exits 1 naming the busy port. Failed specs are not rerun alone (the specs share one stack's store in file order), and `--slow-tests` and `--no-rerun` are refused. Other arguments (`-g <grep>`, `--repeat-each=<n>`) pass through to Playwright. It still shares Vite's `node_modules/.vite` with any other dev stack of the checkout (`pnpm dev:agent`, a `util/playwright/` check), so do not run it beside one.
- `util/overloadTest.mjs` (`pnpm --silent test:overload [--runs N] [--cpu N] [--testTimeout MS] [files or vitest args]`): the gated tests under the reference overload. It runs `util/agentTest.mjs --force --no-rerun <args> --maxWorkers=3` `--runs` times (default 3) with eight busy-loop burners (`node -e`), the run and the burners pinned to one CPU (the last one `taskset -pc` lists, or `--cpu`), so the run gets about 1/9 of a CPU with deschedules of seconds. `--testTimeout` is forwarded only when given (the gate's own timeout is the one to check against: a 60 s hang guard, so slowness alone does not fail a run, and the load exposes tests that depend on real time or the scheduler; investigate each failure); `--maxWorkers` is fixed and refused; a bare `--` is dropped. With no files the whole gated suite runs. It exits 1 naming each failed run, and 2 on a usage error or when the overload broke (a burner that could not start or exited during a run; that run's result does not count). Each run is a supervisor (the same file with `--supervise`) in its own session and process group, holding the burners and the run, so they share one scheduler autogroup; it reports the run's result over IPC and stays until the runner kills that whole group (a Vitest left by a dead wrapper included). The runner also kills the group on exit and error, and on SIGINT or SIGTERM sends it SIGTERM, then SIGKILL once the supervisor ends or after 3 s at the latest. A supervisor whose runner is gone kills its group, and a burner whose supervisor is gone exits. A supervisor that ends without a result counts as a broken overload. Linux only (`taskset` from util-linux); elsewhere it exits 2 with a message.
- `util/agentTestReporter.ts`: a Vitest reporter that prints nothing while tests run and then, per failure, `FAIL <file> > <suite> > <test>`, the error message, the diff (or `expected:`/`actual:`), the in-repo stack frames (no `node_modules`, Node internals, or anonymous frames; none when no frame is in the repository), the cause chain, and that test's console output (`--silent=passed-only` is not needed: logs are buffered per task and printed only under a failure), then, only with `test:agent --slow-tests` and when any passed test took longer than its threshold, a `SLOW <n> passed tests took over <t>s in this run (a warning, not a failure; ...)` line with the ten slowest (`<s>s <file> > <suite> > <test>`) and a count of the rest, then one summary line (`util/agentTestResults.mjs` `summaryLine`, which the wrapper also uses after a rerun): `OK <n> passed, <n> skipped (<files>, <s>s)` or `FAIL <n> failed, <n> passed, ... (<k> of <files> failed, <s>s)`. Module and suite errors (import failures, `beforeAll` throws) and unhandled errors are listed the same way. With `RISU_REPORT_RESULTS_FILE` set it also writes the run's per-file counts and failure names there (see `util/agentTest.mjs` above). Diffs, values, logs, and frames are capped.
- `vitest.lucideImports.ts` `lucideImports`: rewrites `import { Icon, A as B } from "@lucide/svelte"` into one `@lucide/svelte/icons/<file>` default import per icon, from a map read off the package's own re-export lines, keeping the statement's line count. Without it every test that reaches an icon imports all of them (about 15 s per file); pre-bundling the package (`deps.optimizer`) instead gives the icons their own Svelte runtime and breaks mounting them. A statement with a name the map lacks is left on the main entry. Tests only: the build tree-shakes and the dev server pre-bundles.
- `util/agentDev.mjs` (`pnpm dev:agent` / `pnpm dev:human`): runs the server (`node --watch server/src/main.ts`, so a server edit restarts it) and Vite (`--host <host> --port <port> --strictPort`, `RISU_DEV_SERVER` pointed at that server, `https` when `server/ssl/certificate/server.key` and `server.crt` exist) as children, each leading its own process group (kept after its leader exits); Ctrl+C or SIGTERM sends SIGTERM to each leader (the `node --watch` supervisor passes it to the server), waits until each group is empty, and sends SIGKILL to a group still alive after 10 s; when one child ends the rest is stopped, and nothing is started once stopping began. Before anything starts it applies the server's `readListenConfig` to the environment it will pass (a bypass off loopback or a bad flag ends it there) and checks both ports (taken: it exits with a message). Vite starts only once the server accepts connections (120 s at most): `node --watch` keeps waiting for an edit after a failed start, so only that first start is checked, and a later restart may fail while code is being edited.
  - Both modes bind to `127.0.0.1` (`util/agentDevHost.mjs` `resolveAgentDevHost`): `localhost` is a secure context, which the login (`crypto.subtle`) and the service worker need. `RISU_AGENT_DEV_HOST` binds elsewhere (an IPv6 address without brackets); `tailscale` looks up this machine's Tailscale IPv4 (`tailscale ip -4`, `100.64.0.0/10`) and binds only to it (an error without one), and over plain HTTP that origin is no secure context.
  - `agent`: server 6419, Vite 6418, `RISU_AGENT_DEV_AUTH_BYPASS=TRUE` (the server refuses it off loopback, `server/src/listenConfig.ts`), Vite cache `node_modules/.vite-agent` (two Vite processes sharing one cache collide while optimizing dependencies), storage `save-agent/` unless `RISU_SAVE_DIR` is set (then used as it is). The runner prepares it before starting the server, so a `--watch` restart keeps it, and holds `save-agent.lock` (its pid, written with `wx`) for its lifetime: a second `dev:agent` in the same checkout, also on other ports, refuses to start while the owner runs. A lock left by a killed runner is not taken over (two runners could both see the dead pid); the message says to delete it.
  - `human`: server 6001, Vite 5174, the normal login, storage `save/` (or `RISU_SAVE_DIR`), Vite's default cache. It can run beside an agent stack.
  - `util/agentDataSandbox.mjs` `prepareAgentDataSandbox` (`RISU_AGENT_DATA_MODE`): `clone` (default) rebuilds `save-agent/` from `save/` on every start: `data/resources.sqlite` and `data/vectors.sqlite` through SQLite's online backup (read-only source, so a running human server is fine) and `assets/` as hard links (copies across filesystems; safe because asset writes are staged and renamed, never rewritten). `server/` (password, known keys, Web Push keys and subscriptions), `backups/`, `diagnostics/`, `data/request-history.sqlite`, `models/`, and top-level files are left behind. `keep` reuses an existing sandbox (clones when there is none), `fresh` starts empty. The copy is built in `.save-agent.staging-*` and swapped in (`save-agent.previous-*` during the swap); a symbolic-link sandbox, a non-directory, or a sandbox inside the source (or the reverse) is refused.
- `playwright.config.ts`: specs in `e2e/**/*.spec.ts`, one worker, the system Chrome (`/usr/bin/google-chrome`, override with `RISU_CHROME`; no browser download), `baseURL` `http://localhost:5201`. `globalSetup` is `util/playwright/globalSetup.mjs`, which starts one isolated stack per run.
- `util/playwright/stack.mjs`: `startStack({ serverPort, vitePort, serverEnv })` runs `server/src/main.ts` in a fresh temporary working directory (with `RISU_SAVE_DIR` pinned to its `save/` and the shell's `RISU_HOST` and `RISU_AGENT_DEV_AUTH_BYPASS` dropped, so the store starts empty, the repository `save/` is never touched, and auth is real) and the Vite dev server with `RISU_DEV_SERVER` pointing at it (`serverEnv` adds to the server's environment only, e.g. `NODE_OPTIONS` with a check's `--import` preload; without one the server gets a `fetch` egress tripwire, `deniedEgress()`); `isolateContext(context)` keeps a browser context's HTTP requests on local hosts and `unexpectedEgress` filters the expected blocks (CDN stylesheets, the hub listing). `util/playwright/offline.sh <command>` runs a check in a user and network namespace with loopback only (`unshare -rn`): the boundary that keeps the stack, the browser, and the mocks off public services, whatever the transport; `stop()` ends both and deletes the directory. `openApp(page, baseURL)` answers the node-password prompts and waits for `loadedStore`. `clearSafeBootAttempts(contextOrPage)` clears safe boot's `risu.safeBoot.attempts` counter before every page load, for a check that loads the app three times within its 10 s settle window (a reload followed by `openApp` loads it twice; the tabs of one context share the counter), which would otherwise boot safe behind its notice dialog. Page code reaches app modules with `await import("/src/...")`, which is the same module instance the app uses; a two-client check opens a second browser context (tabs of one context share `localStorage`).
- `util/heap/snapshot.mjs`: reads a `.heapsnapshot` (Chrome DevTools or CDP `HeapProfiler.takeHeapSnapshot`) larger than V8's maximum string (the `nodes`/`edges` digits straight from the Buffer, the strings one by one) and analyses it: `summarize`, `diffSnapshots` (by node id, two snapshots of one page), `retainers` (shortest retainer paths over strong edges), `dominators` (retained sizes), `heapReport` (the heap object counts: proxies, asset-tuple proxies, large proxies, likely duplicated large strings: same size and first 1,024 characters, all a snapshot keeps; `FontFace`/`CSSStyleSheet`). Retained sizes charge a WeakMap value to its key, as DevTools does. `util/heap/analyze.mjs` is its command line (`summary`, `diff`, `strings`, `paths`, `top`, `report`; usage in its header; a 500 MB snapshot needs `node --max-old-space-size=16000`). It prints no string content unless asked (`--prefix N`) and no property key unless asked (`--keys`), so user snapshots stay local data.
- `util/upstream/checkBinCompat.mjs` (not in `pnpm test`; usage in its header): runs upstream RisuAI's own `.bin` database decoder and boot defaults on this server's output, against one of two upstream targets per run (`UPSTREAM_TARGETS` in `util/upstream/upstreamHarness.mjs`; one target per process, because the loader hooks stay registered): `--target legacy` (the default, `669b12ce`, whose `decodeRisuSave` returns the database) or `--target current` (`f50b5942`, whose `decodeRisuSave` returns `{ database, kv }`; the check fails on another shape, or on a non-empty `kv` for a legacy-format file). Metatron's export is the legacy format, which both targets read. `RISU_UPSTREAM_DIR` names an upstream checkout that holds the target's commit; every upstream source is read from that commit with `git show`, so the checkout's HEAD and working tree do not matter. `RISU_UPSTREAM_MSGPACKR` and `RISU_UPSTREAM_FFLATE` name package directories of the target's exact library versions (`packages`, from upstream's lockfile at that commit: msgpackr 1.10.1 and fflate 0.8.2 for both targets); another version, an unknown target, or a checkout without the commit ends the run with `ERROR` (exit 2). It never installs, builds or starts the upstream app. Run each target in turn:
  ```bash
  P=<a node_modules/.pnpm holding msgpackr@1.10.1 and fflate@0.8.2>
  RISU_UPSTREAM_DIR=<upstream checkout> RISU_UPSTREAM_MSGPACKR=$P/msgpackr@1.10.1/node_modules/msgpackr RISU_UPSTREAM_FFLATE=$P/fflate@0.8.2/node_modules/fflate node util/upstream/checkBinCompat.mjs --target legacy
  ```
  then the same with `--target current`; each ends `OK` (exit 0) or `<n> check(s) failed` (exit 1).
  - `upstreamHarness.mjs` `loadUpstream` loads upstream's client code into plain Node with `module.registerHooks`: the `REAL` modules (`storage/risuSave.ts`, `storage/database.svelte.ts`, `bootstrap.ts`, and what `setDatabase` and `checkNewFormat` call) are transpiled with `typescript` (no Svelte compiler: a rune evaluated at load fails loudly); `EXTRACT` cuts `checkCharOrder` out of `globalApi.svelte.ts` and `safeStructuredClone` out of `polyfill.ts` (and, for the current target, `migratePluginStorage` and the `pluginStorage` singleton out of `process/coldstorage.svelte.ts`, over the real `process/pluginStorageStore.ts`, with in-memory cold storage reads, writes and removals in its prelude); `OVERRIDES` fix the web build's platform flags, the `DBState` object and `uuid`'s `v4`; every other import is a recording stub whose property reads, writes, calls, constructions, key enumeration and descriptor reads are recorded (except the inert `then` probe), and a recorded use the check has not approved fails it. Each target lists its approved uses one by one, by exact label, per phase (both: store and storage-instance construction at load, `changeLanguage` in the boot pass; current also `changeLanguage` and `requiresFullEncoderReload.state=` in the migration pass). The export names each loaded module reads are collected from the emitted code before anything links.
  - Without arguments: (1) `encodeUpstreamDatabase` on the codec fixture and an edge-case object, decoded by upstream's `decodeRisuSave` with no console output (no fallback path) and compared structurally (bytes for binary values, own `undefined` kept apart from a missing key, `int64` reported as such); (2) a synthetic upstream library (the codec fixture plus lore, chat toggles, a folder, expired trash, a module, a second preset and persona, an installed plugin with two inline `pluginCustomStorage` values, a sentinel key) imported through this server's upstream import routes in process and exported through the RisuAI-compatible export routes without and with keys: the archive read with `indexArchive`, upstream's decoder and this server's must agree, and the result is compared with the input library for group controls, ordered chats/messages (including times and existing message ids), global/local/module lore fields, folder identity and order, retained prompt fields in every preset, persona icons, module membership/regex/triggers, and the plugin with its inline values, with explicit allowances for refreshed trash, local toggles, generated message ids and selection roots; (3) current target only: upstream's plugin storage migration, in its boot order (`setDatabase`, `migratePluginStorage` before plugin loading, then `makeColdData`'s `pluginStorage.load()` and a flush), on each decoded export with a fresh singleton: no throw, console warning or error, the inline keys moved into a valid index record that `_coldpluginIndex` names, their inline copies gone, and each value read back by a fresh store from the persisted index equal to the export's; (4) upstream's boot after a restore (`setDatabase`, `checkNewFormat` with `checkCharOrder`, `assignIds`) on each decoded export: no throw, console warning or error, and every character, chat and message kept, `characterOrder` complete, existing chat ids unchanged and every resulting chat id non-empty and unique. The exporter's id-less empty-chat branch is covered by `upstreamExport.test.ts` and accepted by this boot rule; the synthetic route scenario retains stored chats. `--bin <file>` runs the decoder comparison, the migration pass (current target) and the boot pass on an existing `.bin` and identifies inputs by ordinal and prints array counts and fixed failure categories only, without names or property paths (safe to report for private files; an upstream backup's counts include its cold-storage stubs). ## Flows

- Production: `pnpm build` produces `dist/`, which only the Hono self-host server (`pnpm run server`, `server/src/`) or Docker serves. Served any other way (static hosting), the client shows the `NodeServerRequired` notice.
- Development: `pnpm run server` plus `pnpm dev`.
- CI: the forge is a self-hosted GitLab, and `.gitlab-ci.yml` runs one job, `check`, for pushes to `metatron` and `main` and for merge requests that target them (`workflow: rules`; nothing else starts a pipeline). The job runs on the `node:24` image with `ONNXRUNTIME_NODE_INSTALL_CUDA=skip` (no CUDA provider download in the postinstall), runs `corepack enable` (so `pnpm` is the `packageManager` version), and then `util/ci/check.sh`: `pnpm install --frozen-lockfile`, `pnpm check`, `pnpm format:check`, `pnpm check:tests`, `CI=1 pnpm test` (no `slow` tag), and `pnpm build`, stopping at the first failure with its exit code and printing each step's duration. `pnpm test:slow` and `pnpm test:e2e` are not in CI. The pnpm store is cached at `node_modules/.pnpm-store` (`PNPM_STORE_DIR`, which the script passes to `pnpm install`), keyed on `pnpm-lock.yaml`; inside `node_modules` the formatting check, Vitest, and the test inventory skip it. The job uses no secrets and no `save/` data. A person can run the same script locally (it checks the Node and pnpm versions first); agents keep using `pnpm --silent test:agent` (V1).
- There is no desktop build. The Tauri shell (`src-tauri/`), its `@tauri-apps/*` packages, the updater, and the Python llama.cpp sidecar were removed.

## Coupling

- The service worker URL conventions are coupled to `bootstrap.ts`, `globalApi.getFileSrc`, and `characterCards.characterURLImport`. The `risuCache` name and `/sw/img/<hex>` keys are shared with the page's direct asset lookup; the worker handles `/sw/register/<hex>` and `/sw/img/<hex>`, with `/sw/check/<hex>` only the client's lookup fallback.
- The unbundled worker's `signAssetAuth` is a hand copy of `src/ts/storage/serverAuth.ts` `createAuth`: ES256 over UTF-8/base64url JSON, `{ alg: "ES256", typ: "JWT" }`, and `{ iat, exp: iat + 300, pub }`. Its key location matches `src/ts/util.ts` `getKeypairStore("node")`: IndexedDB `DPoPDB` version 1, store `node`, key `dpop`, containing `{ privateKey, publicKey }`. Keep both signers in parity with a test that runs the worker against a real WebCrypto key and verifies its token with `server/src/routes/auth.ts` `createAuthStore().checkAuth`.

## Invariants

- Bump the version in both places. `package.json` `version` is not the app version.
- The service worker paths (`/sw/register` and `/sw/img` with hex paths, fallback `/sw/check`, `/sw/share/*`) and Cache Storage `risuCache` are a contract with three consumers.
- The asset signer only reads the page's key: abort any IndexedDB upgrade so an absent database stays absent, never create the `node` store, and close every opened connection (including a late success after a blocked open). Cache only successful tokens, not keys or missing-key results; retain the destination/method/origin/client-id gate and the single 401 retry.

## Recipes

- Change the build: `vite.config.ts`, plus the consumers of any env var (`bootstrap.ts`). Verify with `pnpm check`, `pnpm --silent test:agent`, `pnpm build`.
- Change the service worker: edit the hand-written `public/sw.js` and check its contracts with `bootstrap.ts:registerSw`, `globalApi.getFileSrc`, `characterURLImport`, and `manifest.json`. For direct assets, preserve the `/sw/init` capability response, interception allowlist, and signer/key-location parity with `serverAuth.ts` and `util.ts`; verify worker tokens with the server's `createAuthStore().checkAuth`.
- Release: bump `version.json` and `appVer`.
- Add a slow test: first try to make it fast (a test-only option for the limit, as
  `createScriptWorkerPool`'s `syncHostTimeoutMs` and `sleepCaps`). Tag it `slow` only when the cost
  is the subject: a real wall-clock limit, a real production limit, cold loads of every tokenizer, or
  a fresh Node process. Tag a test with `{ tags: ["slow"] }` (the timeout goes in the same object)
  and a whole file with a `/** @module-tag slow */` comment, then update the slow-test selection table in
  `Tests`. The tag is defined in `vitest.config.ts`; an undefined tag fails the run.
  Run `pnpm check:tests`: it fails while the table and the tags disagree.

## Tests

Agents run `pnpm --silent test:agent` for the default fast suite. Use
`pnpm --silent test:agent --tags-filter=slow` for affected slow coverage or
`pnpm --silent test:agent --all` for both. `--force` bypasses the tree cache;
file filters and other Vitest arguments pass through. Passing output is a current
run result, not a permanent property of this guide. A `FLAKY` block in a passing
run names tests that failed in the full run and passed when their file ran alone:
a warning, not a failure, and not something to fix in an unrelated change. A test
that keeps showing up in `node_modules/.cache/agent-test/flaky.jsonl` is a
candidate for its own V3 fix, checked with `pnpm --silent test:overload <file>`.

Slow tests cover real wall-clock/production limits, cold tokenizers, or fresh Node
processes. Select them when touching the last column below. Discover current tags
with `rg -n 'module-tag slow|tags:.*slow' server/src shared src` rather than relying
on a count or timing estimate.

Unit tests run behind a network guard. `vitest.setup.ts` routes the global `fetch`,
`WebSocket`, Node's undici global dispatcher (every hop of a Node `fetch`, redirects included),
and, under happy-dom, the start of every happy-dom `Fetch`/`SyncFetch` (its fetch, XHR, and
script, link, and iframe loads, each redirect hop) and the `WebSocket` of every window it builds
later (an iframe's) through `vitest.testNetwork.ts`. happy-dom's `settings.fetch.interceptor` is
not used: 20.14.5 leaves an async task pending when `beforeAsyncRequest` throws. The policy
allows `data:` and `blob:` URLs and the exact loopback origins
(`http(s)://127.0.0.1|[::1]|localhost:<port>`) a test registered; `ws:`/`wss:` follow their
HTTP origin. Everything else is refused, relative URLs included: the call throws or rejects as a
failed request would (an XHR fires `error`), and the setup's `afterEach` fails the test even when
its code caught the error. The globals are assigned directly, so `vi.stubGlobal("fetch", ...)`
replaces the guard and `vi.unstubAllGlobals()` restores it. A test that needs the network stubs
`fetch` (or the module that fetches) or starts a loopback server and registers it:
`allowTestLoopbackOrigin(origin)` returns the unregister function; server tests call
`server/src/tests/testSupport.ts` `allowListenerOrigin(server)` once the server listens (a
`node:http`/`node:net` server or a `ws` `WebSocketServer`), which unregisters on `close()`, and
`startUpstream` does it itself. A registration outlives `afterEach`, so a `beforeAll` upstream
serves the whole file; the setup's `afterAll` fails the file when an origin is still registered
or a refusal came after the last `afterEach`. A test that wants a refused connection registers
the dead port (`onTestFinished(allowTestLoopbackOrigin("http://127.0.0.1:1"))`). Not guarded:
`node:http`/`https`/`net`/`tls` sockets opened directly (the Lua egress transport
`server/src/lua/egress.ts`, `ws` package clients), and worker threads and child processes, which
have their own globals. `vitest.testNetwork.test.ts` (happy-dom) and
`vitest.testNetwork.node.test.ts` (node) cover the policy and the installed guards.

### Test rules

Two gates decide whether a test belongs in the default suite. Both are checked from the
test's code, not from a guess about how likely the code is to regress.

- Determinism (mechanical). A gated test must not depend on real wall-clock time, CPU
  time, or the scheduler. That rules out elapsed-time and throughput assertions
  (`toBeLessThan` on a duration, "N items in under M ms"), a sleep used to let other
  work finish before an assertion, a poll with a real-time cap over real socket or
  file I/O, a real production deadline that test work must beat (a staging TTL, an
  echo delay, a regex or Lua budget, a worker's boot cap), and a cold worker, child
  process, tokenizer, or module graph booted under such a deadline. The gate's Vitest
  timeout is not such a deadline (see below). Fix by controlling the clock:
  `vi.useFakeTimers` (add `"Date"` to `toFake` when the code reads `Date.now`), an
  injected `now`, a deferred or latch that holds the provider or the slot, a call-through
  `setTimeout` spy, or a test-only limit option. Boot the module graph once in a
  `beforeAll` (as `characterCardsPngImport.test.ts` does) so each case does not pay for
  it, and warm worker pools before a region a real deadline covers. A test whose subject is the real limit
  itself goes to the `slow` tier instead (see Recipes).
- Contract over implementation (judgment). A test earns its place when a plausible
  wrong implementation would fail it. A test that only pins call order, private state,
  a mock's return value, or fixed data the task did not touch protects nothing and
  breaks on refactors; do not add it, and prune it when it starts costing time. Add
  tests only for code the task changes.

A module mocked in more than one test file gets one shared, typed factory in a `tests/`
directory (STRUCTURE V7): `src/ts/tests/alertMock.ts` `createAlertMock(overrides)` returns
every export of `src/ts/alert.ts` (`vi.fn()`s whose awaited helpers resolve with a dismissed
dialog's answer, empty stores), and its defaults `satisfies typeof import("src/ts/alert")`,
so a new or reshaped export fails `pnpm check`. Load it inside the hoisted factory and pass
the file's own handles: `vi.mock("src/ts/alert", async () => (await
import("src/ts/tests/alertMock")).createAlertMock({ alertError: mocks.alertError }))`. A
partial mock over `importOriginal` needs no factory. Every other client test that mocks
`alert` uses it.

`pnpm check:tests` (`util/testInventory.mjs`, plain Node: no test run, so no human gate) reads
`vitest.config.ts` and `playwright.config.ts` as source and applies their patterns with each
runner's own code (Vitest's tinyglobby file glob, Playwright's `createFileMatcher` on the
absolute path). It fails when a test file under `src`, `server`, `shared`, `util`, `e2e`, or
the root is collected by neither runner, by both, or only by the other one (Playwright owns
`e2e/**/*.spec.ts`, Vitest every other test file); when a `slow` tag and the table below
disagree (a row names its file, then "(the whole file)" for a `@module-tag slow` or each
tagged test's title in double quotes, `...` standing for any text), or a test's `tags` is not
a literal string or an array of literal strings in the options object; or when a non-test file under `src`,
`server/src`, or `shared` imports a `tests/` path or a `*.test`/`*.spec` module (a `.svelte`
file through Svelte's parser, template expressions included). A config shape it cannot read (a
non-literal pattern, an object spread, an unsupported pattern-list spread, or a duplicate key,
`projects`, `typecheck`, `respectGitIgnore`, no
`testDir`) is an error; teach the script before using one.

The gate's Vitest timeout is a hang guard, not a performance budget (decision D5 of the timing
plan, 2026-10-22): a test whose result does not depend on real time may take as long as the
machine's load makes it take, and only a test that never settles should fail on the timeout. So
`vitest.config.ts` sets `testTimeout` and `hookTimeout` to 60 s instead of Vitest's 5 s and 10 s, and a gated
test or hook gets no explicit shorter budget (a `slow` test keeps its own). Slow tests are reported
on request instead of failing: `pnpm --silent test:agent --slow-tests` lists the ones over 1 s.
Real-time dependencies (sleeps, real deadlines, bounded polls, elapsed-time assertions) are still
V3 violations at any timeout. The static inventory of gated tests that broke the determinism
gate, with a disposition per spot (keep, rewrite, move to `slow`, delete), is
`docs/audit/timing-dependent-tests-2026-10-19.md`. It was completed on 2026-10-22, and the plan
that did it is archived (`docs/archived-plan/README.md`, Timing-Dependent Tests). It is a historical
record now: a new real-time dependency is a V3 violation to fix in its own change, not a new row.
The plan's close-out checked the whole gate two ways, and both are worth repeating after a change
to shared test infrastructure: three runs of `pnpm --silent test:overload` at once on different
CPUs (`--runs 1 --cpu N` each, about 31 min), and four `pnpm --silent test:agent --force` runs at
once with no CPU limit. Verify a timing fix under load with
`pnpm --silent test:overload <files>` (three runs, default timeouts; see `util/overloadTest.mjs`
above). The slow tier is not run under it. `server/src/tests/testSupport.ts`
`waitFor` has no polling deadline by default: the test's Vitest timeout reports a condition that
never holds as a failure. An explicit `timeoutMs` cap is for slow-tier tests only; prefer awaiting
the event where one exists.

## Known Hazards

- Import lucide icons as plain names (`import { X, Check as Ok } from "@lucide/svelte"`). Another form (a type, `icons`, a default or namespace import) keeps that statement on the package's main entry, and every test that reaches it imports all the icons again (about 15 s per file); `vitest.lucideImports.test.ts` fails on it.
- A Vitest file that reaches the settings views or the records needs the client environment (happy-dom): the records use Svelte's client `$state`, so `@vitest-environment node` fits only pure schema tests. Install a flat fixture with `src/ts/storage/tests/installFlatDatabase.ts`.
