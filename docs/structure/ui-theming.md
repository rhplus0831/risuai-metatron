# UI Components and Theming

## Scope

- Owns:
  - the Svelte component tree below `App.svelte` (chat screen, message rendering components, sidebar),
  - the reusable GUI primitives,
  - popups and portals,
  - theme colors and CSS tokens,
  - GUI sizing, tooltip, and longpress actions,
  - chat branches.
- Paths:
  - `src/lib/ChatScreens/*`
  - `src/lib/SideBars/*`, except `Scripts/`, `LoreBook/`, `CharConfig.svelte`
  - `src/lib/Others/*`, except the files owned by other guides
  - `src/lib/UI/*`, except `Realm/`, the model pickers, `PromptDataItem.svelte`, `MainMenu.svelte`, `Title.svelte`
  - `src/lib/UI/GUI/*`, `src/lib/UI/NewGUI/*`
  - `src/lib/Mobile/*`
  - `src/lib/Playground/PlaygroundMenu.svelte`
  - `src/styles.css`
  - `src/ts/gui/*`, except `highlight.ts` and `codearea/`
- Not here:
  - Screen selection in `App.svelte` → `app-shell.md`.
  - Settings pages → `settings-i18n.md`.
  - Markdown/HTML rendering internals → `cbs-rendering.md`.
  - The send path → `chat-pipeline.md`.

## Files

Chat:

- `ChatScreen.svelte`: layout theme switch (`waifu`, classic); a custom background that finishes loading after a newer one was chosen is dropped. Mounts `BackgroundDom`, `TransitionImage`, `ResizeBox`, `ChatList`, and the module menu.
- `DefaultChatScreen.svelte`: input box, send/reroll (see `chat-pipeline.md`), and menus. The Stop button's rotating circle takes `chat-process-stage-1`–`4` (blue preparing, pink memory, green generating, purple finishing) from the selected chat's newest staged job (`chatStageOf($jobStages, currentChatRef())`, `src/ts/process/jobStages.ts`), else `chat-process-stage-0`; another chat's job never colors it. In auto mode `.autoload` (green, declared after the stage rules) wins over every stage. The class names and hex colors are kept as they are, since `display.customCSS` can target them. The main composer's placeholder comes from `composerPlaceholder.ts`: `Setup required` while the chat's binding is incomplete, nothing in the playground, else `persona → character` from the names the rows show. The placeholder takes the composer's own font, including a custom CSS size, so the persona is cut at 8 characters: Chromium clips the end of the one-line placeholder without an ellipsis, which would hide the character on a phone. `white-space: pre` on it keeps one line, so the composer's height does not depend on the names, and keeps the leading space of ` → character` for a persona without a name. While the binding is incomplete both composers are `readonly`, not `disabled`, so they keep their text, focus, and the focus hotkey, and Enter still opens the setup; pasting an image is ignored, and typing a `/` command waits for the setup. Text that other controls add (a suggestion, an additional asset) still lands in the draft, which a send keeps until the setup is done. The hamburger menu pins with `setChatMeta(ref, { pinned: true })` and unpins by unsetting `pinned`. Chooses home, playground, the closed chat (`ClosedChatScreen.svelte`, while `selection.chatOpen` is false), or chat.
  - The `metatron` theme adds `metatron-chat-theme` to the chat scroller; `src/styles.css` styles each message (`.risu-chat`) as a card under it. Any other non-`waifu` theme keeps the classic layout.
  - Owns the loaded row window and accepts guarded trims from `Chats`. Unfolding adds `messages.length - foldedIndex` to preserve the folded window's oldest row. Binds `Chats.revealing` to hide the separate greeting with `visibility: hidden` until the opening batch finishes revealing, and `Chats.holding` to skip the scroll-driven load-more while rows are held (held rows add no height, so the top would stay in reach and every scroll event would load another page). Screenshot capture waits for all rows and their current markdown (`whenRendered`) with `loadPages = Infinity`, releases any reveal batch, suspends trimming/containment, and restores the previous window and scroll offset for the same chat in `finally`. `src/lib/ChatScreens/screenshotCapture.ts` sets `includeQueryParams: true` so html-to-image keeps original and thumbnail URLs in separate cache entries.
  - Message jumps go to a message id: a bookmark's index (`ScrollToMessageStore`) names it once, when the jump starts, and a search hit carries it. Search claims a request once. Both run through `runMessageJump` (`messageJump.ts`) under one screen-owned jump: a newer bookmark or search jump, a chat switch, a replaced transcript, or destroy stops the older one; each await is followed by a check of the selected and shown chat and a fresh lookup of the message by `Message.chatId`; a folded target unfolds the window before scrolling and ringing it. Both jump types suspend trimming.

The transcript (`Chats`), the first greeting (`.default-chat-screen > .risu-chat`), the composer, and the rows around them carry `chat-screen-content-width` (`src/styles.css`): one centered column of `min(--chat-screen-width, 100%)`. A new row in the chat scroller gets the class too, and a popup tied to the composer (the composer menu) is positioned inside the composer row so it follows the column instead of the viewport or scroller edge.
- `Chats.svelte`: imperatively mounts rows keyed by chat and `Message.chatId`. The structural diff tracks row identity/order, streaming entry, window and reload inputs, not message text; each row's disposable effect handles its own text and display updates. Streaming reaches only that chat's active row. Opening windows mount and reveal newest rows first, then arm older rows after render or interaction, or at a diff that changes the shown rows (a diff that shows the same rows, such as the reload a module change makes right after a switch, keeps the staging); a row reveals once rendered and its unfinished images in the transcript's view have loaded (lazy images outside the view, which do not load while hidden, never hold it), or at a 1200 ms deadline. Rows that come in above every shown row (an opening's deferred rows, a loaded or unfolded page) are held out of the layout (`chat-row-held`, `display: none`) until their current instance has rendered and the reader is not scrolling; appended or newer rows never wait. Showing them registers a no-op non-passive `wheel`/`touchstart` listener (the scroll gate) so a new scroll waits for the main thread, shows the rendered rows together an animation frame later (after the gate's commit, and after that frame's input and scroll events, which can still cancel), and lifts the gate a frame after their growth commits; without the gate, a scroll starting during the shown rows' layout still raced their commit. Chrome finishes a running scroll animation in this reversed scroller at its distance from the top, so content growing above the view mid-animation (reproduced with real wheel input, not CDP wheels, which do not animate) moves the reader up by the grown height. The reader is scrolling from a wheel, scroll, or touch event until `scrollend`, or 400 ms without one where `scrollend` is missing, and while a finger is down. The containment observer skips held rows and observes them again when shown. Screenshot capture, `suspendTrim`, and `whenRendered` show held rows at once. Screenshot mode bypasses staging and containment. At the bottom, appends trim only old rows while keeping at least `CHAT_ROW_CAP` (150) plus visible rows and one load page; folds, screenshots, jumps, and open editors block trimming. Scrolling follows a scroll anchor: `start` keeps a row's top at the scroller's top, `end` keeps the bottom, none leaves the position to the reader. Opening a chat (not folded, captured, or jumping) anchors the newest row's start, or the bottom while it streams. With `autoScrollToNewMessage`, a reply that arrives whole (locked or not) anchors its start, and a streamed one (`isMessageStreamed`: chunks only, so this tab's or another's stream, and never a continue that has not streamed) the bottom until its lock ends, then its start unless `scrollToReplyStartAfterStreaming` is off; both apply only while the reader follows (`followsLatest`: an anchor or the bottom, or `alwaysScrollToNewMessage`), otherwise a reply sets the new-message indicator. A generation that never streamed ends at the newest start only while the anchor holds, so a reader who scrolled is left alone. The reader's own send moves an anchored transcript to the bottom. Swiped rerolls (`DefaultChatScreen`) anchor the newest start through `scrollToLatestMessage` when the reader followed before the swap, as the new-message button does; `openRoute` (a notification) sets `ShowLatestMessageStore`, and the screen then shows the newest start even for a chat that was already open. A `ResizeObserver` on the transcript and scroller re-applies the anchor before paint; wheel, touchmove, a press on the scroller itself (its scrollbar), and scroll keys outside inputs release it, and so does a jump or screenshot (`suspendTrim`), during which new replies only set the indicator. The anchor scrolls by measured offset, not `scrollIntoView`, which can move ancestor scrollports too. An `IntersectionObserver` contains only distant rows, with measured intrinsic size.
- `Chat.svelte`: one message. Branching clears `pinned` on the new chat; with `createFolderOnBranch`, a source chat that `chatFolderOf` lists under no folder (none, or a dangling `folderId`) and its branch go into a new "Branches of" folder. Controls, bookmarks (`toggleBookmark`), TTS button, `displaya`, partial edit, and `renderGuiHtmlPart` for custom GUI HTML. Message theme branches are `mobilechat`, `cardboard`, `customHTML`, and classic. Both original-message editors bind a separate `draft`, initialized on opening and cleared on save; a long-press cancel keeps the draft for reopening but never changes `message`, the display, partial-edit source, or storage. Original and translation edits for stored message rows (`idx >= 0`) automatically open a popup once per edit-mode entry unless `settings.ui.disableAutoPopupMessageEditor` is true (Interaction settings, default false). Closing that popup writes its text to the draft and saves through `edit()` or `saveTranslationEdit()`; a refused write keeps the inline editor open with the draft, without reopening the popup. Translation popup saves suppress another auto popup until translation edit mode is left. A changed message target (chat ref or message id), changed draft or translation target, ended edit mode, superseded session, or destroyed row discards the popup text and closes only its owned session. `messageEditPopup.ts` owns the pure eligibility rules and the stable-height rule: an active stored-row editor whose text contains a newline or exceeds 600 characters uses a fixed scrollable inline area, except in `cardboard`, `customHTML`, and `mobilechat`. Both inline areas retain an expand button and popup hotkey regardless of the auto-popup setting. With `clickToEdit`, a click on the message body opens the original-message editor, except a click inside a `risu-form` form, a `risu-btn` or `risu-trigger` element (any tag), or an interactive control (`input`, `textarea`, `select`, `button`, `label`, `a`, contenteditable). Each row gets its owning `ChatRef` from `Chats.svelte` (`chatRef`; other mounts default to the selection at mount): message actions, Lua buttons, manual triggers, and forms address that chat, not the selection at the event. A Lua button reloads its row only when its job started, so a refused button keeps typed values beside it. A bookmark preview passes no `messageId` and tells the row it streams through `streamingOverride`. `isEditing` exposes open original/translation editors to the trim guard. `ChatBody` is keyed only by the reload pointer; `whenRendered` loops until the bound body stays the same across its render wait and DOM flush, including replacements from `ReloadGUIPointer`. Body-less rows settle immediately. Optional `pendingReveal` hides the greeting's whole row without changing its layout. A row renders again in place (`chatBodyRevision`) when its chat's first save lands, when its lock ends, and when a retry round of failed display transforms includes its message (`cbs-rendering.md`). The memory limit line: with `showMemoryLimit`, the row whose message id is its chat's `lastMemory` (the first history entry the server's last prompt kept, set before the final token recheck, so it can be off by the entries that recheck removed) gets a `memoryLimitThickness` top border; an explicit `isLastMemory={false}` (bookmark previews, the greeting) never draws it.
- `ChatBody.svelte`: `markParsing`, which handles translation and parsing, then `{@html}`. `whenRendered` waits for the current parse and its DOM update for ordered reveal and screenshot capture (forwarded by `Chat` and `Chats`), rechecking replacement parses after each flush. The rendered auto-translate path's initial empty result is not settled: the wait includes its delayed `translated` update and the resulting real parse. Raw streaming settles immediately and remains visible as raw text.
  - While a render is pending it shows `lastParsed`; only the newest render (`parseRun`, kept by its retries) writes it, so an older render that settles later does not show again (`ChatBody.svelte.test.ts`).
- `Suggestion.svelte`: reply suggestions through `requestChatData`.
- `ContextMeter.svelte`: the composer's context line, mounted above the composer row (the composer container is a column: this right-aligned line, then the row with the textarea and buttons, which anchors the composer menu) and keyed by the open chat (a switch starts closed); not shown in a group chat or while `settings.ui.contextMeter` is off. It reads the newest message whose `generationInfo.context` passes `parseContextReport` (`shared/contextReport.ts`, [chat-pipeline](chat-pipeline.md)), scanning only the message list and each message's `generationInfo`, so streaming text does not rerun it; with no valid report anywhere it falls back to the newest `inputTokens / maxContext`, and with neither it renders nothing. Line (the `context-meter-chip` button, whose text truncates at the end): the kept count by `contextMeterTurnUnit` ("18 turns" / "18 messages"), with memory then "summarized", "gap", or "memory on" by `coverage`, then the share of the prompt budget (`maxContext − maxResponse`), joined by " · "; a legacy fallback shows only its percent. When `fixedShare` exceeds `contextMeterFixedWarn` it adds "fixed N%" and takes the danger tone. It leads with a gauge icon, or a lore icon (and a label clause) when the lore budget rejected entries, unless the chat's `loreBudgetWarnOff` is set. When the report's `memory.budgetReduced` lists HypaV3 token-mode amounts the server reduced to fit the max context, a danger-toned "memory reduced" mark follows the icon (outside the truncating text) and the label gets a clause; there is no per-chat off switch. While the chat's background HypaV3 summary task (`memoryTaskStatus`, `src/ts/process/memoryTasks.svelte.ts`) is queued or runs, a secondary-toned mark with a spinner follows the icon, also outside the truncating text ("summary queued", "summarizing", or "summarizing 3/8" once the total is known), and the label gets a clause; it is shown only beside a chip, since a task is handed off only after a send wrote its reply's report. The popover (`Portal` to the body, fixed above the line when space allows, below it otherwise, or within the viewport when neither side has room; below dialogs and alerts, repositioned on resize, scroll, and composer growth) uses one scale, the prompt budget (`maxContext − maxResponse`): the headline is the input over the budget with its percent (`inputOfBudget`) and a muted line on where the budget comes from (`budgetFrom`); without a budget it shows the input over `maxContext` and the `noBudget` note. The header carries a settings icon button (its `aria-label` and `title` name the counting basis, `basis(unit, warn)`) that opens the `interaction.contextMeter` section through `openSetting`, and the Close button. Above the headline, a background summary block shows that task: while it is queued or runs, its state and the note that the breakdown is the last reply's; after a task this mount saw run ends `done` with `lastCommittedRevision`, that the new summaries are stored for later sends to use as the history needs them (HypaV3 may defer them while the history fits), until the meter's source changes (a new reply, or a continue that rewrites the report), which ends the notice for good (a task that ended before the mount, or committed nothing, shows nothing); while the last terminal is `failed`, the failure, the redacted error, and a link to the memory settings page. The composition bar groups the sections in a fixed order: fixed (every kind but memory and history, neutral, danger-toned while `fixedShare` exceeds `contextMeterFixedWarn`), memory, history; with a HypaV3 report carrying `memory.reserved` and `summarizeIn` it ends, after a flexible spacer, with the unused reserve hatched (`context-meter-reserve`, `max(0, reserved − memory.tokens)`), over `max(prompt budget, entries + max(reserved, memory.tokens))`; a tick marks the warning level at `contextMeterFixedWarn`% of the prompt budget on that scale. A legend lists each present group with its tokens and the empty reserve, then one text line gives the fixed share (danger-toned with `fixedShareOver` past the level). The sections follow largest first, each dot in its group's color, then a muted counting-difference line for a non-zero `adjustment` (`otherLine`, with `otherHelp` as its title) and the approximate note. The history block reads past, then future, then memory: the kept count in the setting's unit with the other unit's in parentheses (`historySent`, emphasized), the totals (`historyTotal`), the messages left out with their tokens and, with `memory.summarized`, the tags ("summarized into memory" and, past it, "left out unsummarized" in the danger tone; without it the report gives no reason, so no tag); with the summarize points, the history runway: a caption with the history tokens sent and `summarizeIn` left, a bar filled to the history tokens over `history + max(summarizeIn, lookaheadIn)`, a solid tick `summarizeIn` past the fill and, while `contextMeterLookahead` is on and the report has `lookaheadIn`, a dashed tick that far past it (the hidden lookahead leaves the scale too; the server counts in the summarizer's terms), label lines for both ("in ~N tokens of history", or at 0 the next send or "passed"; the summary label names `memory.prepared` as ready summaries, with the explanation as its title) and, while the reserve holds room the memory sent does not fill, a note that the HypaV3 reserve lowers the room with a link that opens the memory settings page (`settingsOpen`, `SettingsMenuIndex = MEMORY_SETTINGS_MENU`); then, indented, the memory: the HypaV3 budget as `tokens / budget` (or the memory line for other kinds), with `budgetReduced` a danger-toned line that the budget was reduced to fit the current max context and each reduced amount as `configured → applied`, and the coverage sentence only without `summarized`. Then the lorebook activation budget: the budget row alone while nothing was rejected (plus the note and the way back while `loreBudgetWarnOff` is set), else the danger-toned bar, the report's named entries and "and N more" past them, and a link that sets or unsets the chat's `loreBudgetWarnOff` through `setChatMeta`. It closes on Escape (unless an alert, terminal notice, or binding dialog is above it; focus returns to the line), a pointer down outside, focus leaving both it and the line, its close button, when its source disappears, or when the line leaves view or the viewport is too short to show it. While the composer has text (`draft`, passed with `generating` by `DefaultChatScreen`), the line adds a displacement estimate ("if sent ≈ −2", "≈ −8+" past the saved trim queue) and the popover an estimate block: `displacement` over the report's `trim` ledger with the draft and the last reply counted in `jobTokenScope()` (each without its `<Thoughts>` block, plus `trim.perMessage`; a continue's `replyPrefix` subtracted). The estimate needs the report on the chat's last, enabled message, `historyDigest` of the messages before it unchanged, the same token scope, effective `maxContext` and `maxResponse`, no send or job in the chat, a complete binding, no memory configured (it may run instead of the trim loop), and no `presetChain`; a continue whose overflow reaches the queue's last entry shows none. The reply count is kept per basis, so typing recounts only the draft; a new basis or an emptied draft resets the count, and a failed count hides the estimate.

GUI primitives (`src/lib/UI/GUI/*`):

- `Button`, `IconButton`, `CheckInput` (`disabled` prevents toggling and dims with theme tokens; `indeterminate` displays the native mixed state and a dash), `ColorInput`, `NumberInput`, `TextInput`, `SelectInput`/`OptionInput` (`SelectInput` forwards native select attributes, including accessible labels and data attributes, and carries `risu-select`), `SegmentedControl` (buttons carry `aria-pressed`; optional `label` makes the container a named `role="group"`, `describedBy` sets its `aria-describedby`, and `margin={false}` drops the bottom margin settings pages use; a bound value that matches no option shows no indicator), `SliderInput` (`-1000` means disabled; a touch or pen drags only after it moves sideways past a slop, a vertical move is left to page scrolling, and a tap sets the value through its click), `OptionalInput` (nullable), `MultiLangInput`/`MultiLangDisplay`.
- `TextAreaInput`: textarea or contenteditable with CBS highlight and autocomplete. Both branches support the popup-editor hotkey and contextmenu/long-press opening with `settings.ui.longPressToPopupEditor` at every field height unless `popupEditor={false}`. `popupEditor` defaults to `"auto"`: the expand button and its right padding show for heights `"32"`, `"36"`, or `"full"`, or `"default"` with `$textAreaSize >= -2`; `true` always shows the button and padding, and `false` disables all popup access. The button uses the existing popup-editor label. `popupLanguage` selects the popup language. A changed bound value, `popupEditorContext`, or open run discards write-back and closes only the owned session; a newer session or component destruction also prevents write-back. ## Flows

- Desktop: `App` → `Sidebar` + `ChatScreen` → `DefaultChatScreen` → `Chats` → `Chat` → `ChatBody`.
- First greeting: rendered as a separate `Chat` with `idx: -1`. `fmIndex: -1` means `firstMessage`. `fmIndex >= 0` selects `alternateGreetings[fmIndex]`. The chat screen, the CBS registry, triggers (`v2GetFirstMessage`) and regex `repeatBack` read it through `shared/greetings.ts` (`greetingIndex`, `greetingText`, `nextGreetingIndex`, `previousGreetingIndex`): a missing, non-integer or out-of-range index reads as -1. Not converted yet: `server/src/prompt/assemble.ts` (prompt assembly) and `src/ts/characters.ts`, `src/ts/gui/branches.ts` and `src/lib/Others/HypaV3Modal/utils.ts` index `alternateGreetings` directly.
- Popups: `PopupButton` → `popupStore` → `App` renders `PopupList`, which closes on the next document click.
- Theme: at boot `bootstrap.ts` calls `updateColorScheme`, `updateTextThemeAndCSS`, `updateAnimationSpeed`, and `updateGuisize`. The display settings call the same functions. Plugins can call them via `apiV3`.

## State

- Components mutate the settings through the record views (`settings.ui.*`, `settingsViews.svelte.ts`) and the characters through the character module's records (`selectedCharacter()`, `characterList()`), and rely on the records' write-through saves: each write queues the record it changed (`persistence.md`).
- Invalidation signals:
  - `ReloadGUIPointer`: structural changes.
  - `ReloadChatPointer`: message re-render, by `reloadChatKey` (`m:` and the message id; the greeting `i:` and its index), so a row keeps its counter when messages before it are added or removed. Mounted row effects subscribe through the store; a changed entry remounts only its row.
  - Reassigning an array after an in-place mutation, e.g. `chat.bookmarks = [...]`.
- Theme DB fields: `theme`, `colorScheme`, `colorSchemeName`, `customColorScheme`, `textTheme`, `customCSS`, `textAreaSize`, `sideBarSize`, `textAreaTextSize`.

## Invariants

- Use theme tokens (see STRUCTURE.md U1). To add a color: a root variable, an `@theme` token, a `ColorScheme` field, `updateColorScheme`, and presets.
- Message identity: `Chats` keys a row by the chat and `chatId` (a message without one by its index); see `updateChatBody` and the per-row effect above for remount conditions. `Chat.updateRow` changes only supplied position/streaming fields or display-only `name?: string` and `img?: string | Promise<string>` props; name/image updates never reset the `ChatBody` key. Never read every row's text in the structural effect; per-chunk transcript JavaScript work must not grow with mounted row count.
- Chat structure operations go through the chat module (`createChat`, `deleteChat`, `reorderChats`, `setChatMeta` for `folderId`; `persistence.md`) and select with `changeChatTo`/`selectChat`; `chatPage` is derived from the per-tab selected chat id and is never assigned. Components never `bind:` a chat field directly: bind a getter/setter pair that calls the module, or a synced editing copy. A locked message (`isMessageLocked`: generating, or its final write not yet acknowledged) has its edit, delete, and regenerate controls disabled; reroll and chat deletion alert `chatGenerating` while the chat holds a lock.
- HTML boundaries:
  - `ChatBody`, `BackgroundDom`, suggestions, and plugin panels use `{@html}` only on sanitized parser output.
  - `renderGuiHtmlPart` whitelists tags and allows only `https` links.
  - Custom CSS is injected via `CustomCSSStore` and must stay disabled in `SafeModeStore`; so must the `customHTML` theme's GUI HTML (`Chat.svelte` renders the classic row instead).
- A list of inputs over a list that can change while one of them has focus keys its rows by entry and binds each input to the entry captured at mount (getter/setter functions that drop a write once the list no longer holds it), never `bind:value={list[i]}` in an unkeyed `#each`: Chrome fires `change` on a focused, edited control while removing it, and an index binding resolves `list[i]` at that moment. The lorebook and character asset editors follow this ([characters-modules](characters-modules.md) Invariants).
- Runes and legacy stores are mixed: `$state`/`$derived`/`$props`/`$bindable`/snippets alongside `writable` stores, `.subscribe`, `createEventDispatcher`, and `on:save`. Match the local component.
- Primitive prop convention: an `interface Props`, destructured with `$props()`, `$bindable()` for mutable values, callback props (`onclick`, `onchange`), and `children: Snippet`.

## Known Hazards

### Issues

- Rows bound by index carry only their owner's id as `popupEditorContext` (`PromptDataItem` in the prompt template, `RegexData` in a regex list, a plugin's textarea argument, which uses the plugin's name): when another client reorders the owner's rows while a popup is open and both rows hold the same text, the row stays mounted and its popup writes into the row now at that index. Plugin rows with duplicate names (kept by `setPlugins` and the upstream backup import) share a context the same way. The rows have no ids, and the row object's identity would change on every refreshed record list, which would discard unchanged drafts.

### Limitations

- Content that grows inside rows already shown above the view while a scroll animation runs moves the reader by the grown height (Chrome, reversed scroller): images swapped in late by `checkImg` (`.root-loaded-image` reserves no height), lazy images, a row re-rendering (CBS, translation, a reload pointer), and a far row whose `contain-intrinsic-block-size` estimate differs from its rendered height when it comes near. `Chats.svelte` holds rows that come in above the view until they have rendered and the reader stops scrolling; a new path that adds rows above the shown ones goes through that hold. A fix would keep a reader anchor once the hold releases (the visible row nearest the view's top and its offset) and restore it at `scrollend`, not mid-animation. Reproduce with real X wheel ticks (headed Chrome on WSLg through XTest); CDP `Input.dispatchMouseEvent` wheels do not animate. Decision: deferred by the owner (2026-10-27).
- A far row's fixed-position or overflowing custom content is contained while it is far. Near rows are deliberately uncontained; do not apply `content-visibility` to every row or to the transcript ancestor. Decision: near rows stay uncontained (`src/styles.css`, `.chat-message-container.far`).
- `src/lib/Others/PopupEditor.svelte` keeps only the text across its Monaco toggle: the textarea or the Monaco model is recreated, so the selection moves to the end and the undo history is gone (an undo after switching back does nothing). The toggle's contract (`819a6295d`) promises the text only; keeping one model across the switch is a larger editor-lifetime change. Decision: text-only contract kept (2026-10-29; observed by the [cross-plan review](../audit/cross-plan-2026-10-29.md#noted-not-recommended-to-fix) with a real Monaco instance).
- Older rows do not rerender merely because the chat length changes. Length-dependent CBS updates when that row next renders (edit, reload, remount, etc.); restoring the old last-five key would add unnecessary renders on every append. Decision: old rows are deliberately not re-rendered (`docs/research/risunest-ideas.md`).
