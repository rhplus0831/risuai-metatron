**B02 · P1 · A late push mutation can reverse the newest confirmed intent.** D11 says “A late answer stamps success or clears pending evidence only if its generation is still the newest,” and Q3 proposes “no server change.” Endpoint membership is idempotent for repeated identical writes. PUT canonicalizes the endpoint, suppresses a recent identical healthy registration, otherwise replaces its entry and refreshes bookkeeping. DELETE filters that endpoint and succeeds when it is already absent. But the routes read the request body **before** joining the server writer, and neither carries the client generation. An older PUT delayed before writer admission can therefore run after a newer DELETE has returned 204. Ignoring the PUT answer leaves the endpoint registered. Opted-out reconciliation can subsequently return without another DELETE once pending removal evidence is cleared. The reverse ordering can remove a newly enabled endpoint.
