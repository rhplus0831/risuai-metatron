# Audits

Reports of this repository read for defects. The folder is what the audit read, so pick it by scope:

| Folder                                | Read                                                                                                 | Look here for                                                         |
| ------------------------------------- | ---------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------- |
| [codebase/](#codebase)                | The code across plans and subsystems: one class of defect, the whole tree, or the cause of a symptom | What is known about data loss, performance, or test timing as a whole |
| [finished-plans/](#finished-plans)    | The code one finished plan left, or several plans' combined result, read against the plan            | What an audit found in a feature after its plan was done              |
| [plan-runner/](plan-runner/README.md) | A plan's text, read against the code before the plan is implemented                                  | Which premises of a plan were wrong before it ran                     |
| [guides/](#guides)                    | `STRUCTURE.md`, Doc Maintenance and the guides, read against the source                              | The last full guide audit and what it changed                         |

A report whose scope is a plan is named after the plan in both plan folders, so `rg --files docs/reports/audits | rg <plan>` lists a plan's audit before it ran and after. A check of this code against another project's fixes is a survey: see [fork-data-loss-crosscheck](../surveys/fork-data-loss-crosscheck.md) and [pocketrisu-fix-crosscheck](../surveys/pocketrisu-fix-crosscheck.md).

Each row below gives the commit the report read. A report is a snapshot of that commit: a defect it lists may be fixed, and the report often says so in a later note.
